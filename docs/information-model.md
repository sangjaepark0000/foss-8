# 수업 프로젝트 정보 구조

> 초기 설계 초안입니다. 현재 프로토타입은 화~월 학사 주차를 사용하며, 시험 면제 날짜와 회의록 기록·제출 기간을 구분합니다. 최신 동작은 [실행 안내](../README.md)와 [주차별 안내 데이터](../foss8/data/weeks.json)를 확인하세요.

2026-10-27 작성. [구조화 데이터](../data/course-project.json)는 안내서 v1.3과 저장소의 팀 결정을 정리한 초안이다. 실제 수업 진행, 작업 완료, GitHub 업로드, LMS 제출 여부는 아직 조사하지 않았다. 원문 전사와 구분하며, 현재 CLI의 안내 로직에는 아직 연결하지 않았다.

## 읽는 단위

할 일은 주차 표가 아니라 **담당자 + 실행 조건 + 필요한 입력 + 결과 + 기한 + 완료 증거**로 읽는다.

| 정보 | 의미 | 연결 |
| --- | --- | --- |
| 프로젝트 | 기능·산출물·목표의 대상 | 팀, 기능 담당자, 평가기준 |
| 팀·개인 | 행동과 책임의 주체 | 역할, 액션, 실행 기록 |
| 수업 이벤트 | 학습 내용과 예정·실제 시점 | 액션의 학습 시점, 활동 기간 |
| 활동 기간 | 수업 실제 종료 ~ 다음 수업 실제 시작 | 할 일의 실행 맥락 |
| 기록 대상 기간 | 회의록에 포함할 활동의 날짜 범위 | 제출 회차 |
| 평가 기간 | 평가 실적을 집계하는 범위 | 개인·팀별 기준; 경계 미확정은 그대로 보존 |
| 마감·발표 이벤트 | 특정 결과를 확인하거나 제출하는 시점 | 제출물, 액션 |
| 제출물 | 회의록·보고서·발표자료의 특정 회차 | 기한, 책임, 목적지별 파일 규칙 |
| 시나리오 | 반복 가능한 액션과 의존 관계 | 입력, 담당, 출력, 완료 조건 |
| 실행 기록 | 실제로 누가 무엇을 했는지 | 시나리오 단계, 시각, 원본 버전, 증거 |
| 평가기준 | 시기·대상별 요구 조건 | 증거, 배점, 해석 미확정 사항 |

활동 기간은 화면을 구성하는 단위다. 제출 마감이나 평가 집계 기간을 활동 기간에 강제로 맞추지 않는다. 수업 종료 시각이 없으면 정확한 경계도 미확정이다. 휴강은 학습 완료 이벤트가 아니며, 시험과 보강은 일반 수업과 구분한다.

## 회의부터 제출까지

| 액션 | 담당 | 필요한 정보 | 결과·확인 |
| --- | --- | --- | --- |
| 회의 준비 | 전원 | 이전 결정, 미완료 작업, 기록 기간 내 개인 활동, 막힌 점, 다가오는 마감 | 안건·현황. 준비 단계의 묶음은 운영 제안 |
| 회의 진행 | 전원 | 안건·진행 상황 | 참석 정보, 결정과 이유, 다음 작업별 담당·기한·이슈 |
| 회의록 작성 | 백지훈 | 회의 내용, 활동 로그, 부록 B 양식 | 원본. 회의 중 실시간 작성 |
| 내용 확인 | 전원 | 원본 | 확인된 버전 |
| GitHub 업로드 | 미지정 | 확인된 원본, 저장 규칙 | Markdown URL 및 commit/PR |
| PDF 생성 | 미지정 | GitHub의 확인된 Markdown | PDF 내용·페이지 확인 |
| LMS 제출 | 박상재 | PDF, 회차별 파일명, 제출 위치·마감 | LMS 제출 확인 기록 |

원문이 안내하는 변환 경로는 GitHub 파일 열기 → 브라우저 인쇄 → PDF 저장이다. 작성 완료·GitHub 업로드·LMS 제출은 각각 다른 상태다. 업로드 뒤 원본이 바뀌면 제출 PDF가 어떤 버전에서 만들어졌는지도 확인해야 한다.

| 목적지 | 형식 | 이름·위치 | 이름의 기준 |
| --- | --- | --- | --- |
| GitHub | Markdown | `docs/meetings/YYYY-MM-DD.md` | 회의 실시일 |
| LMS | PDF | `[WEEK9] 회의록_foss-8.pdf` 등 | 제출표의 수업 회차 |

예를 들어 10/30 수업 후 회의했다면 GitHub 파일 날짜는 실제 회의일이다. 그 회의가 포함되는 회의록 #5의 LMS 이름은 `[WEEK10] 회의록_foss-8.pdf`다. 같은 문서의 날짜와 WEEK가 같은 주차 번호를 의미하지 않는다.

근거: [회의록 규칙·제출표](guide/12-minutes.md), [양식](guide/appendix-b-minutes-template.md).

## 보여줄 정보

첫 화면은 선택한 개인과 현재 시각을 기준으로 만든다. 고정된 ‘이번 주’ 열에서 일을 가져오지 않는다.

| 영역 | 표시할 정보 |
| --- | --- |
| 지금 실행 가능 | 다음 액션, 담당, 기한, 필요한 입력, 근거 |
| 선행 조건 미확인·막힘 | 필요한 수업·승인·자료·담당자, 확인할 내용 |
| 기한 임박 | 제출물, 남은 단계, 목적지, 고정 마감 |
| 기한 초과·이월 | 원래 기한, 남은 액션, 확인된 상태 |
| 수업 후 예정 | 예정 학습 시점, 준비할 수 있는 입력, 실제 진행 미확인 표시 |

제출물을 열면 기록 기간, 담당별 단계, GitHub/LMS/이메일 규칙, 원본 버전, 완료 증거를 보여준다. 평가 화면에서는 개인·팀·프로젝트별 적용 기간, 기준, 관측 실적, 미확정 해석을 보여준다.

‘현재 실행 가능’과 ‘이번 평가에 필요’는 별도 표시한다. 수업은 액션의 학습 예정 시점이지, 이미 할 줄 아는 사람의 선행 작업을 금지하는 조건이 아니다. 필수 의존성·권한·담당자의 준비 상태를 따로 확인한다.

## 해석과 상태의 규칙

- 예정일이 지났다고 수업을 들었거나 작업을 완료했다고 추정하지 않는다.
- 미확인은 미완료·미충족과 다르다. 실제 실행 기록이 없는 초안으로 점수를 계산하지 않는다.
- 완료와 기한 준수는 별도다. 지각 제출도 완료일 수 있다.
- 기간이 바뀌어도 미완료 작업과 원래 기한은 유지한다.
- 실제 진도가 밀려도 고정 제출일은 별도 공지 없이 이동시키지 않는다.
- 회의록 제출 번호, WEEK, 회의일, 기록 기간, 활동 기간을 각각 저장한다.
- 원문 규칙, 승인된 팀 결정, 운영 제안, 실제 관측을 구분한다. 근거 충돌은 감추지 않는다.
- `team-context.md`의 ‘이번 회의록 WEEK6’ 등은 당시 기록이며 현재 회차를 뜻하지 않는다.

현재 미확정: 주간 평가 집계 경계, 실제 수업 진도·시각, 3기능 배점 조정, 일부 단계 담당자. 중간보고서가 11/5에 타 팀 배정 상태를 요구하지만 기여 수업은 11/13인 점도 남겨 둔다. 미배정 상태라면 실제 상태와 계획을 적는다.

## 데이터 이용과 검증 범위

`data/course-project.json`의 주요 컬렉션은 `actors`, `events`, `cycles`, `deliverables`, `artifact_rules`, `workflows`, `criteria`, `open_questions`, `executions`, `views`다. `source`는 저장소 루트 기준 근거 경로다. `null`은 미확정이며 `executions`는 실제 관측을 아직 수집하지 않아 비어 있다. 워크플로 단계의 `after`는 같은 워크플로 안의 ID를 참조한다. `all_members`, `feature_owner`, `other_member`는 실행 시 실제 개인으로 해석할 역할이다.

이번 단계는 원문 기반 정보 구조화다. Lean 증명, 자동 점수 계산, 현재 상태 동기화, CLI 화면 구현은 포함하지 않는다. 날짜 순서·ID 참조·배점 합계와 출처 경로를 우선 검사한다. 이후 실제 실행 기록을 붙일 때 GitHub와 LMS 증거를 각각 확인해야 한다.
