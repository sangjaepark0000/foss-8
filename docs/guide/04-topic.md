## 4. 주제 정하기 (2~3 주차)

주제는 자유입니다. 이 프로젝트의 목적은 '대단한 프로그램'이 아니라 GitHub에서 4명이 함께 만들고 기록을 남기는 경험이므로, 확실하게 동작하는 주제가 좋습니다.

<a id="section-4-1"></a>

### 4.1 좋은 주제 고르는 질문 3개

| 질문 | 이유 |
| --- | --- |
| 4명이 기능 4개로 나눌 수 있는가? | 1인 1기능이어야 각자 브랜치·풀 리퀘스트·커밋 기록이 고르게 남음 |
| 첫 동작을 1~2주 안에 볼 수 있는가? | 7주차에 브랜치를 만들자마자 '뭔가 되는' 코드를 올릴 수 있어야 함 |
| API 키·외부 서버·큰 데이터 없이도 시작할 수 있는<br>가? | 샘플 데이터 파일 하나로 시작하고, 외부 연동은 나중에 붙이는 것이 안전 |

<a id="section-4-2"></a>

### 4.2 규모

<table>
<tr><td>핵심 기능</td><td>4개(1인 1기능) + 공통 코드(저장·읽기, 메뉴). 5개 이상이면 제안서에서 줄이도록 요청</td></tr>
<tr><td>기능이란</td><td>사용자가 메뉴 하나·명령 하나로 쓰는 단위. 예: &#x27;거래 추가&#x27;, &#x27;월별 통계&#x27;, &#x27;예산 경고&#x27;, &#x27;그래프 저장&#x27;</td></tr>
<tr><td>MVP(중간발표, 10주차)</td><td>기능 2개가 실제 데이터로 동작 + README대로 실행됨</td></tr>
<tr><td>기능 동결(13주차)</td><td>이후 새 기능 금지. 남은 기간은 버그·문서·릴리스</td></tr>
<tr><td>코드량</td><td>전체 300~1,000줄 정도이나 넘겨도 무방함</td></tr>
</table>

### 4.3 유형별 예시

| 분류 | 예시 주제 | 도구(pip) | 난이도·비고 |
| --- | --- | --- | --- |
| CLI 도구 | 가계부, 할 일 관리, 폴더 정리 자동화, 날짜·<br>단위 계산기, 학점 계산기 | 표준 라이브러리(csv, json,<br>argparse) | ★ 쉬운 난이도 |
| 데이터 분석 | 부산 공공데이터(교통·대기질·인구) 분석 리<br>포트, 시각화 대시보드 | pandas, matplotlib | ★★ 데이터를 먼저 CSV로 확보(공공<br>데이터포털 data.go.kr) |
| 간단한 앱 | 메모장, 미니 게시판, 설문·투표, 시간표 관리 | streamlit(권장, Python만으<br>로 화면) 또는 flask | ★★ 로그인·회원가입은 만들지 않기 |
| 게임 | 텍스트 기반 퀴즈, 가위바위보, 끝말잇기, 타<br>자 연습, 2048 | 표준 라이브러리, pygame | ★★ 텍스트 게임 권장 |
| 도구·자동화 | GitHub 활동 통계 스크립트, 문서 생성기, 디<br>스코드 알림 봇 | requests, discord.py | ★★★ 토큰은 저장소에 올리지 않기<br>(9.5) |

### 4.5 피해야 할 주제

- 로그인·회원가입·결제가 중심인 웹 서비스 — 인증에 시간을 다 쓰고 기능이 안 남음

- 실시간 크롤링에 전적으로 의존 — 대상 사이트가 바뀌면 발표 날 멈춤. CSV 데이터 + 갱신은 선택 기능으로

- 유료 API가 꼭 필요한 것 — 비용·키 공유 문제. 무료 범위·샘플 응답으로 대체
