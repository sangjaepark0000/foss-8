## 14. 마무리: 릴리스·최종보고서·최종발표 (13~15 주차)

<a id="section-14-1"></a>

### 14.1 v1.0.0 태그와 릴리스 (14주차, 수업 9주차 '프로그램 출시하기')

버전은 수업에서 배운 대로 X.Y.Z(메이저.마이너.메인터넌스)를 씁니다.

1\. 13주차(11/27)부터 기능 동결: 새 기능 풀 리퀘스트 금지, 버그 수정·문서·정리만. 리뷰·품질 담당 주도로 [1.3절](01-overview.md#section-1-3) 완성 기준 5개 점검 → 부족한 것은 이슈로 등록해 해결

2\. README 최종 확인(14.2) → 풀 리퀘스트로 병합

3\. 14주차(12/4): 소스트리에서 main 체크아웃 → Pull → 상단 태그 → 태그 이름 v1.0.0 → 태그 추가 → Push 창에서 모든 태그 푸시 체크 → Push (수업 9주차 절차)

4\. GitHub 저장소 → Releases → Draft a new release → Choose a tag에서 v1.0.0 선택 → 제목 v1.0.0 → 본문에 기능 4개 요약 + 설치·실행 방법 + 스크린샷 → Publish release (태그 페이지의 zip 다운로드만으로도 인정되지만 릴리스 노트가 있으면 결과물 점수에 유리)

5\. 4주차 보강 주(12/7~11): 팀원 1명이 새 폴더에 클론 → pip install -r requirements.txt → README의 실행 명령 → 기능 4개 확인. 결과를 회의록 #10에 기록. 안 되면 README를 고쳐 v1.0.1

> \[TIP\] 발표 당일 네트워크·봇 장애에 대비해 시연 녹화 영상을 반드시 준비하세요. 스크린샷 3장(입력 → 처리 → 결 과)을 README에 넣으면 데모 GIF를 대신할 수 있습니다.
