## 16. 도움 받기

<a id="section-16-1"></a>

### 16.1 막혔을 때 순서

1\. [부록 E](appendix-e-faq.md) FAQ에서 오류 메시지로 검색

2\. 팀 채널에 질문 — 팀원 중 누군가는 같은 문제를 겪었을 확률이 높음. 24시간 내 응답 규칙

3\. 저장소 이슈에 question 라벨로 등록 (다른 팀도 볼 수 있음)

4\. 교수 이메일(shoh0320@pknu.ac.kr) 또는 수업 시간 질문. 아래 양식으로 보내면 답이 빠름 (수업 3 주차 '질문하는 방법')

<a id="section-16-2"></a>

### 16.2 질문 양식

```text
[팀명 / 이름] 하려던 일: 소스트리에서 feature/add-record 브랜치를 Push
실행한 것: 상단 Push → 브랜치 체크 → Push 버튼
오류 메시지(전체 텍스트): remote: Permission to ... denied to ...
환경: Windows 11 / Git 2.51 / 소스트리 3.x / 저장소 주소
이미 해 본 것: 소스트리 옵션 → 인증에서 계정 재로그인
```

<a id="section-16-3"></a>

### 16.3 AI 도구 (Copilot, ChatGPT, Claude 등)

- 사용해도 됩니다. 단, 풀 리퀘스트에 올린 코드는 작성자가 설명할 수 있어야 합니다. 발표·리뷰에서 '이 줄은 왜 필요한가?'에 답하지 못하면 집계에서 제외됩니다

- 좋은 사용: 오류 메시지 해석, 명령어 의미 질문, 내 코드의 문제점 찾기. 나쁜 사용: '프로젝트 통째로 만들어 줘', 실행해 보지 않은 코드 커밋, 토큰·개인정보 입력

- 학생 인증(GitHub Student Developer Pack)이 되면 GitHub Copilot을 \`무료로 쓸 수 있습니다 (선택)
