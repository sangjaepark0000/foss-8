### 3.2 주차별 상세

2~5주차: 팀 구성과 제안서 (수업: OSS 기초 → Git 기초 → 발표)

1\. 2주차(9/11): 팀장·역할 결정(2.2), 팀 약속 작성([부록 F](appendix-f-team-template.md)), 채널·회의 시간 확정. 주제 후보 3개를 4장 기준으로 비교

2\. 2주차: 팀장이 GitHub 웹에서 공개 저장소 생성(README·.gitignore(Python)·MIT 포함) → 팀원 3명 협력자 초대 → 팀원은 이메일에서 수락 (7.1~7.2). GitHub 계정이 없는 팀원은 [6.2절](06-tools.md#section-6-2)대로 먼저 만듦

3\. 3주차(9/18) 수업에서 GitHub 가입·토큰·Git 설치·Git Bash 실습(OSS 저장소)을 마침. 이 실습 저장소가 활동 규칙 '저장소 기여 3개' 중 첫 번째

4\. 3주차 회의: 주제 확정, 기능 4개로 나누어 1인 1기능 배정(4.4 표), 제안서(5장 7항목) 분담 작성

5\. 추석 연휴 주(9/21~27): 제안서 완성 → 10/1(목) 18:00 PDF 제출, 회의록 #1 제출. 5주차(10/2) 발표 10분 \+ 질의 5분

6\. 5 주차 이후~10/8: 팀장은 GitHub 웹의 Add file 로 CONTRIBUTING·행동 수칙·requirements.txt·main.py 기본 파일 업로드(7.3). 각자 담당 기능을 이슈 3개 이상으로 등록(8.4) — GitHub 웹에서 하므로 Git 없이 가능

## 원문 12쪽

<!-- source-page: 12 -->
6~9주차: 첫 커밋 → 브랜치 → 첫 풀 리퀘스트 (수업: 소스트리 → 브랜치 → 충돌·풀 리퀘스트)

1\. 6주차(10/9 온라인 수업)에서 소스트리·VS Code를 설치하고 GitHub 계정을 연결함. 팀 저장소를 소스트리 Clone 으로 내려받아 docs/members/&lt;이름&gt;.md 에 자기소개 3 줄을 쓰고 커밋 → Push. 누군가 먼저 올렸다면 Pull 후 Push. 개발 리드는 main.py 뼈대(메뉴 4개가 '준비 중' 출력)를 올림. 6주차까지는 main에 직접 푸시해도 됨 — 한 명씩 순서대로 Pull → 커밋 → Push

2\. 7주차(10/16) 수업의 실습 브랜치 규칙 4개가 그대로 팀 규칙(8.1). 각자 소스트리 브랜치로 feature/기능이름 생성 → 담당 기능의 첫 동작 코드 커밋 → 브랜치 Push. 아직 병합하지 않음

3\. 8주차(10/23) 중간고사: 회의록 없음, 커밋·풀 리퀘스트·이슈 최소 기준 면제. 시험이 끝난 주말부터 브랜치 작업 재개

4\. 9주차(10/30) 수업 직후: GitHub의 Compare & pull request로 첫 풀 리퀘스트 → Reviewers에 팀원 지정 → 리뷰어가 Approve → Merge pull request. 이때부터 main은 풀 리퀘스트로만 바뀜. 팀장은 [7.5절](07-repository.md#section-7-5)대로 main 브랜치 보호를 켬. 2인 1조로 [부록 D-2](appendix-d-git-drill.md#appendix-d-2) 충돌 해결 실습. 중간발표(11/6) 전까지 기능 2개를 병합해 MVP 완성

10~13주차: 중간발표와 타 팀 기여 (수업: 중간발표 → 포크 → 실무 Git → 프로젝트 공개)

1\. 10주차(11/6) 중간발표: 중간보고서 11/5(목) 18:00 제출 → 발표 10분 + 질의 5분, MVP(기능 2개) 실제 시연(13장). 문서 담당은 타 팀이 기여할 good first issue 2개 이상 등록(11.2)

2\. 11주차(11/13) 수업의 '개발자 C' 역할을 팀 단위로 함: 매칭표의 상대 팀 good first issue 중 1개를 골라 댓글로 배정 요청 → 팀장이 Fork → fork에 팀원 협력자 등록 → 담당을 나눠 작업(11.3). 우리 저장소에 온 배정 요청에는 24시간 안에 응답. 상대 팀 풀 리퀘스트는 11/26까지 제출

3\. 12~13주차(11/20, 11/27): 상대 팀 리뷰 반영 → 12/3까지 병합 확인. 우리 저장소에 온 풀 리퀘스트는 48시간 안에 리뷰·병합. 수업에서 배운 어멘드·리버트·스태시로 실수 정리(8.8). 기능 4개 완성 목표

13~15주차: 동결·릴리스·최종발표 (수업: 프로젝트 공개 → Git Bash → 준비 → 발표)

1\. 13 주차(11/27): 기능 동결. 수업 13 주차 '프로젝트에 꼭 포함할 파일'(README·사용자 가이드·CONTRIBUTING·행동 수칙·라이선스)을 기준으로 문서 최종 정비(14.2)

2\. 14주차(12/4): 완성 기준 5개(1.3) 점검 → 소스트리 태그로 v1.0.0 생성·Push(수업 9주차 방법) → GitHub Releases에 릴리스 노트(14.1)

3\. 4주차 보강(12/11): 수업 시간이 팀별 준비 시간. 팀원 1명이 새 폴더에 클론해 README대로 실행 확인 → 최종보고서·발표자료 작성 → 시연 녹화

4\. 15주차(12/18): 최종보고서 12/17(목) 18:00 제출 → 발표 15분 + 시연 + 질의 5분 → 발표자료 이메일 제출
