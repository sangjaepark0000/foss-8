## 10. 활동 규칙 (평가 30 점)

활동 규칙은 '얼마나 꾸준히, 규칙대로 협업했는가'를 GitHub 기록으로 확인하는 항목입니다. 10개 항목 × 3점. 각 항 목은 수업에서 배운 주부터 적용하고, 중간고사 주간(10/19~10/25)은 최소 기준에서 뺍니다.

<a id="section-10-1"></a>

### 10.1 규칙 표

| # | 항목 | 활동 기준 | 적용 기간(최소 총량) | 단위 | 확인 방법 |
| --- | --- | --- | --- | --- | --- |
| 1 | 커밋 | 각자 주 2회 이상 | 6주차(10/9)~12/13, 중간<br>고사 주 제외 8주 → 16회 | 각자 | 저장소 Insights → Contributors |
| 2 | PR | 각자 주 1회 이상 풀 리퀘스트 생성·병합 | 9주차(10/30)~12/13, 7주<br>→ 7회 | 각자 | Pull requests → 검색 is:pr<br>author:@me |
| 3 | 리뷰 | 풀 리퀘스트마다 다른 팀원 1명 이상이 리<br>뷰(Approve)한 뒤 병합. 리뷰어는 돌아가<br>며 | 9주차~ | 팀 | 각 풀 리퀘스트의 리뷰 기록 |
| 4 | 저장소 기여 | 개인(수업 3주차 실습 저장소 OSS), 팀 저<br>장소, 타 팀 저장소(fork 커밋·이슈 댓글·받<br>은 풀 리퀘스트 리뷰 중 1개) — 3개 이상 | 3~13주차 | 각자 | 프로필 활동 |
| 5 | 기여(외부 PR) | 팀이 맡은 타 팀 이슈 1개를 풀 리퀘스트로<br>해결해 병합 (외부 공개 저장소는 선택) | 11~13주차 | 팀 | 타 팀 저장소 Pull requests |
| 6 | Issue 작성 | 각자 주 1회 이상, 작업 전에 등록 | 6주차~12/13, 중간고사 주<br>제외 8주 → 8회 | 각자 | Issues → 검색 is:issue<br>author:@me |
| 7 | 브랜치 전략 | feature/기능이름 브랜치 사용, 9주차부터<br>main 직접 커밋 없음 | 7주차~ | 팀 | 브랜치 목록, 보호 규칙 |
| 8 | Conflict 해결 | 각자 1회 이상 충돌 해결(9주차 실습 포함)<br>+ 회의록에 기록 | 9주차~ | 각자 | 회의록, 병합 커밋 |
| 9 | 문서화 | README(소개·설치·실행),<br>CONTRIBUTING, LICENSE, 행동 수칙 | 최종 기준 | 팀 | 저장소 첫 화면 |
| 10 | 회의록 | 수업 있는 주마다 1회, 총 10회 LMS 제출<br>(12장 날짜표) | 5주차~12/11, 중간고사·최<br>종발표 주 제외 | 팀 | LMS |

채점: 항목당 충족 3점 / 부분 충족(기준의 70% 이상) 1.5점 / 미충족 0점. '각자' 항목은 개인별로, '팀' 항목은 팀 전 원 동일하게 반영됩니다.

> \[참고\] 숫자는 최소 기준이고, 매주 조금씩 하면 자연스럽게 넘습니다. 기준을 채우려는 빈 커밋·의미 없는 이슈는 집계에서 뺍니다. 중간발표 전까지 커밋이 적더라도 7~9주차에 브랜치·풀 리퀘스트를 시작했다면 정상 진행입니 다.

<a id="section-10-3"></a>

### 10.3 항목별 정의·예시·목적

| 항목 | 정의 | 구체적 예시 | 활동 목적 |
| --- | --- | --- | --- |
| 커밋 | 코드·문서 변경을 Git에 저장한<br>기록 | 소스트리 커밋 — 메시지 거래 입력 기능 추<br>가 (#12) | 변경 이력을 기록하고 추적 가능하게 만듦 |
| PR | 브랜치 작업을 main에 반영해 달<br>라는 요청 | feature/add-record → main 풀 리퀘스트,<br>설명에 Closes #12 | 협업자와 변경 사항 공유, 리뷰·병합 절차 |
| 리뷰 | 다른 팀원이 코드를 검토하고 판<br>정 | Files changed에서 \[필수\] 빈 입력 처리 필<br>요 코멘트 후 Request changes | 코드 품질 향상, 버그 사전 발견, 소통 훈련 |
| 저장소 기여 | 저장소에 커밋·풀 리퀘스트·이슈<br>등 실질 활동 | 개인 실습 저장소 커밋, 팀 저장소 개발, 타 팀<br>fork 커밋 | 실질적 활동으로 Contribution 그래프 생성 |
| 기여(외부 PR) | 타 팀·외부 저장소에 풀 리퀘스트<br>로 개선 | 타 팀 good first issue 해결 풀 리퀘스트 | 오픈소스 기여 경험, 낯선 코드 읽기 |
| Issue 작성 | 할 일·버그·질문을 등록 | \[버그\] 한글 입력 시 깨짐 + 재현 절차 | 작업 분담, 문제 추적, 진행 상황 가시화 |
| 브랜치 전략 | 기능별 브랜치로 작업 분리 | feature/add-record, fix/csv-encoding | 안전한 협업, 충돌 예방 |
| Conflict 해결 | 같은 부분을 두 사람이 고쳐 생긴<br>충돌 정리 | 'This branch has conflicts' → [8.7절](08-collaboration.md#section-8-7) | 실무에서 자주 겪는 상황 연습 |
| 문서화 | 외부인이 이해·실행·기여할 수 있<br>게 정리 | README, CONTRIBUTING, LICENSE,<br>행동 수칙 | 사용자·기여자를 위한 안내 |
| 회의록 | 주간 논의·결정·활동 로그 기록 | docs/meetings/2026-10-01.md + PDF<br>LMS 제출 | 의사결정 근거, 활동 기록의 근거 |
