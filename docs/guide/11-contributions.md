## 11. 타 팀 저장소에 기여하기 (11~13 주차)

<a id="section-11-1"></a>

### 11.1 개요와 매칭

- 8팀이 순환으로 짝을 이룹니다: 1팀 → 2팀, 2팀 → 3팀, … , 8팀 → 1팀 (화살표 방향으로 기여).

- 각 팀은 상대 팀 저장소의 이슈 1개를 맡아 풀 리퀘스트 1개로 해결하고 병합까지 확인합니다. 동시에 우리 저장소도 다른 팀의 풀 리퀘스트 1개를 받아 리뷰·병합합니다

- 일정: 11주차(11/13~19) 이슈 선택·배정 요청·Fork → 12주차(~11/26) 풀 리퀘스트 제출 → 13주차(~12/3) 리뷰 반영·병합 확인

- 수업 11 주차 '개발자 C'의 절차(포크 → 풀 리퀘스트 → 승인·병합)를 실제 팀 저장소로 해 보는 것입니다. 크기보다 절차가 중요합니다

<a id="section-11-2"></a>

### 11.2 받는 팀의 준비 (11주차 수업 전까지, 문서 담당)

1\. good first issue 라벨 이슈 2개 이상 등록. 상대 팀이 그중 1개를 고릅니다. 각 이슈에 배경 / 할 일 / 완료 조건 / 관련 파일 이름을 적음 (예: 'README에 Windows 실행 예시 추가', 'summary.py에 빈 데이터 처리', '-- json 출력 옵션')

2\. CONTRIBUTING.md에 '타 팀 기여자' 절이 있는지 확인 ([부록 C-2](appendix-c-templates.md#appendix-c-2) 템플릿에 포함)

3\. 배정 요청 댓글이 오면 24시간 안에 답하고 Assignees에 지정. 받은 풀 리퀘스트는 48시간 안에 리뷰(Approve 또는 구체적인 수정 요청). 첫 기여자에게는 친절하게

<a id="section-11-3"></a>

### 11.3 기여하는 절차 (팀 단위, 수업 11주차 그대로)

1\. 팀 회의에서 상대 팀의 good first issue 중 1개를 고르고, 이슈에 댓글: '○○팀이 이 이슈를 맡겠습니다. 11/26까지 풀 리퀘스트 올리겠습니다.' → 담당자 지정 확인

2\. 팀장: 상대 팀 저장소 페이지 → 오른쪽 위 Fork → Create fork (팀장 계정에 복사본이 생김) → fork의 Settings → Collaborators에 팀원 3명 추가 (7.2와 같은 화면)

3\. 역할 나누기: 구현 1~2명, 실행 확인 1명, 풀 리퀘스트 설명·회의록 기록 1명. 4명이 fork에 커밋하면 각자 '저장소 기여 3개'의 세 번째가 됨

4\. 각자 fork를 소스트리 +(새 탭) → Clone — 폴더는 팀 저장소와 다른 폴더. feature/이슈이름 브랜치를 만들어 작업(8.1) → 커밋 → Push

5\. 구현 담당: fork 페이지 → Contribute → Open pull request → base repository가 상대 팀 원본, head repository 가 우리 fork 인지 확인 → 설명(무엇/왜 Closes #번호/확인 방법/참여 팀원) → Create pull request

6\. 리뷰 코멘트가 오면 24시간 안에 수정 → 같은 브랜치에 커밋·Push하면 풀 리퀘스트에 반영 → 병합되면 링크를 회의록 활동 로그에 기록

> \[TIP\] 수업에서는 fork의 main에 바로 커밋했지만, 팀원 4명이 같은 fork에서 작업하므로 브랜치를 만드는 편이 안전합니다. 원본이 바뀌어 fork가 오래되면 fork 페이지의 Sync fork 버튼으로 최신화합니다.

| 기여 예절 (수업 7주차 '사람들이 중요하다', 9주차 '기여하기') | 이유 |
| --- | --- |
| 상대 팀 CONTRIBUTING.md를 먼저 읽고 그대로 따름 | 우리 팀 규칙과 다를 수 있음. 규칙 준수가 곧 기여 능력 |

| AI로 만든 코드는 직접 실행해 확인하고 설명에 표기 | 검증 없는 코드는 거절 사유 |
| 병합이 끝나면 감사 댓글, 받은 풀 리퀘스트에는 감사 댓글 | 오픈소스 커뮤니티의 기본 예절 |

<a id="section-11-4"></a>

### 11.4 외부 오픈소스 프로젝트 기여 (선택)

- 타 팀 기여 외에 실제 오픈소스에 기여하고 싶으면 수업 6주차 '프로젝트 찾기'의 기준(목표·요건·후보 모으기, CONTRIBUTING과 이슈 트래커가 정비된 프로젝트)으로 고릅니다

- 연습용: github.com/firstcontributions/first-contributions — 초보자용 공개 저장소. Contributors.md에 자기 이름 한 줄을 추가하는 풀 리퀘스트를 보내면 보통 수 분~수 시간 안에 병합됩니다 (활동 집계에는 넣지 않지만 Fork 절차를 두려움 없이 익힐 수 있음)

- 2026년 현재 많은 프로젝트가 AI로 만든 저품질 풀 리퀘스트 때문에 오타·사소한 수정 풀 리퀘스트를 거절하고, 매년 10월의 Hacktoberfest도 풀 리퀘스트 개수 집계를 중단했습니다. 외부 기여는 '개수'가 아니라 '실제로 필요한 개선'일 때만 받아들여집니다

- 병합된 외부 풀 리퀘스트는 최종보고서에 링크로 기록. 응답이 수 주 걸릴 수 있으므로 활동 규칙 5번(타 팀 기여)을 대체하지는 않습니다
