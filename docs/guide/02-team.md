## 2. 팀 구성과 역할

<a id="section-2-1"></a>

### 2.1 팀 구성 규칙

- 2주차(9/11) 수업 시간에 4인 1팀으로 구성. 미리 팀을 꾸린 경우 수업 시간에 알리고, 팀이 없는 학생은 무작위 배정.

- 팀 이름은 영문 소문자·숫자·하이픈만 (예: team-busan) — 회의록 파일명과 저장소 이름에 사용

- 팀 구성 직후 할 일 3가지: 연락 채널 개설(카카오톡 또는 디스코드), 정기 회의 시간 확정, 각자 GitHub 아이디 공유

<a id="section-2-2"></a>

### 2.2 역할 4개

역할은 '조금 더 챙기는 사람'을 정하는 것입니다. 코딩·풀 리퀘스트·리뷰·이슈 작성은 4명 모두 같은 기준으로 평가되 며, 역할만 맡고 코드를 쓰지 않는 경우는 인정되지 않습니다. 수업 3주차의 오픈소스 역할 구조로 보면 팀장이 리더· 메인테이너, 나머지 팀원이 커미터에 해당합니다.

| 역할 | 챙기는 일 | 담당 기능 |
| --- | --- | --- |
| 팀장 | 저장소 소유·설정, 회의 진행, 일정·이슈 정리, 교수와의 소통, 회의록·보고서 LMS 제출 확인 | 기능 1개 |
| 개발 리드 | 프로그램 구조(파일·모듈·데이터 형식) 결정, 공통 코드, 병합 시 기술적 판단 | 기능 1개 + 공통<br>코드 |
| 문서 담당 | README·CONTRIBUTING·행동 수칙 관리, 회의록 작성, 타 팀 기여 창구 | 기능 1개 |
| 리뷰·품질 담당 | 풀 리퀘스트 리뷰가 48시간 안에 되도록 챙김, 버그 이슈 정리, 릴리스 전 실행 확인 | 기능 1개 |

<a id="section-2-3"></a>

### 2.3 팀 약속 (2주차, [부록 F](appendix-f-team-template.md) 양식)

갈등이 생겼을 때 기준이 되는 5줄짜리 약속입니다. 저장소의 docs/team-agreement.md로 올립니다.

- 정기 회의: 주 1회 60분, 요일·시간 고정 (예: 매주 화 20:00 디스코드

- 연락 응답: 채팅 24시간 이내 / 풀 리퀘스트 리뷰 48시간 이내

- 작업 전 이슈 등록, 하루 작업 끝에 푸시 (내 PC에만 두지 않기)

- 결정은 회의에서 다수결, 동률이면 개발 리드가 결정, 결과는 회의록에 기록

- 1주 무응답 → 팀장이 연락 / 2주 → 회의록에 기록하고 교수 상담

<a id="section-2-4"></a>

### 2.4 팀에 문제가 생겼을 때

- 참여하지 않는 팀원: 회의록 '활동 로그'에 사실만 기록(날짜·요청·응답 여부). 활동 규칙의 '각자' 항목은 개인별로 채점되므로 GitHub 기록이 곧 근거가 됨

- 팀원 이탈(수강 취소 등): 즉시 교수에게 이메일. 기능 4개 → 3개로 조정

- 기술적으로 막힘: 이슈에 question 라벨로 등록 → 팀 채널 → 24시간 안에 안 풀리면 교수 이메일 (16장 질문 양식)
